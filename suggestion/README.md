# 问题反馈模块使用说明

## 功能概述

问题反馈模块已集成到网站导航栏，用户可以通过该模块提交各种问题和建议。

## 文件结构

```
suggestion/
├── index.html          # 用户反馈页面
└── admin.html          # 管理员后台管理页面
```

## 功能特性

### 用户端 (index.html)

1. **反馈类型选择**
   - 功能异常/Bug 报告
   - 功能建议
   - 音乐相关问题
   - 界面/体验问题
   - 其他问题

2. **联系方式（选填）**
   - 用户可以留下邮箱或手机号，方便管理员回复

3. **问题描述**
   - 必填项，详细描述问题或建议

4. **提交反馈**
   - 反馈会发送到后台并保存到 data.json 文件
   - 提交成功后显示成功提示

### 管理端 (admin.html)

1. **登录验证**
   - 使用管理员密码登录（密码：xwbdszq）

2. **数据统计**
   - 总反馈数
   - 未读反馈数
   - 今日反馈数

3. **筛选功能**
   - 按类型筛选
   - 按状态筛选（已读/未读）

4. **反馈管理**
   - 标记为已读/未读
   - 删除反馈
   - 实时刷新数据

## 使用方法

### 用户提交反馈

1. 点击导航栏的"问题反馈"按钮
2. 选择反馈类型
3. （可选）填写联系方式
4. 详细描述问题
5. 点击"提交反馈"

### 管理员查看反馈

1. 访问 `/suggestion/admin.html`
2. 输入管理员密码登录
3. 查看所有反馈
4. 可以筛选、标记已读、删除反馈

## 数据存储

反馈数据保存在 `submit/data.json` 文件中，格式如下：

```json
{
  "feedbacks": [
    {
      "id": "1234567890",
      "time": "2025-03-29 12:00:00",
      "type": "bug",
      "contact": "user@example.com",
      "content": "[功能异常] 描述内容...",
      "status": "unread"
    }
  ]
}
```

## 后端 API

### 提交反馈
- **接口**: `submit/api.php`
- **方法**: POST
- **参数**:
  ```json
  {
    "action": "submit_feedback",
    "type": "bug",
    "contact": "user@example.com",
    "content": "反馈内容"
  }
  ```

### 获取反馈数据（管理员）
- **接口**: `submit/api.php?action=get_admin_data`
- **方法**: GET
- **需要登录验证**

### 更新反馈状态
- **接口**: `submit/api.php`
- **方法**: POST
- **参数**:
  ```json
  {
    "action": "update_feedback_status",
    "id": "反馈 ID",
    "status": "read|unread"
  }
  ```

### 删除反馈
- **接口**: `submit/api.php`
- **方法**: POST
- **参数**:
  ```json
  {
    "action": "delete_feedback",
    "id": "反馈 ID"
  }
  ```

## 界面风格

- 与现有页面保持一致的玻璃拟态设计
- 响应式布局，支持移动端
- 底部导航栏统一样式
- 渐变色和阴影效果统一

## 注意事项

1. 管理员密码请在生产环境中修改为更安全的密码
2. 定期备份 data.json 文件
3. 建议定期清理已处理的反馈，避免文件过大
4. 如果反馈数量较多，可以考虑添加分页功能
